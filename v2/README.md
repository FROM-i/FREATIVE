# THE FROM BRAIN — FREATIVE 2.0 (alpha)

**단계를 노드로 바꿔 동시에 분석하고, 노드 사이의 원인 · 충돌을 연결로 남겨 통합 인사이트와 담당별 디렉션을 한 번에 낸다.**

1.x(`../src`, `../knowledge`)는 그대로다. 2.0은 `v2/` 폴더만 쓰고, 1.x의 빌드와 릴리스에 영향을 주지 않는다.

## 1.x와 다른 점

| 1.x의 문제 | 원인 | 2.0 |
|---|---|---|
| 앞 단계 인사이트가 다음 단계에서 빠진다 | 단계가 앞 단계의 요약을 받는다 | 모든 노드가 같은 미션 · 이슈 원문을 받는다 |
| 단계 사이의 연결이 끊긴다 | 관계가 문장 안에만 있다 | 관계를 연결로 저장한다 (`from · to · 종류 · 무게 · 이유`) |
| 결과가 직전 단계만 인용한다 | 마지막 단계만 보고 쓴다 | 아이덴티티 · 에어플레인 · 터널 판단을 모두 거쳤는지 코드가 ID로 센다 |
| 빠진 내용을 알 수 없다 | 기록이 없다 | 판단 몇 건이 인사이트에 쓰였는지 건수로 보여 준다 |
| 노드를 이름만 읽고 넘어간다 | 정의 요약만 전달한다 | 원문을 읽히고 생각한 순서를 쓰게 한다. 못 쓴 판단은 제외한다 |

## 쓰는 순서

1. **세팅** — 분류(마케팅 · 기획 · 디자인 · 개발 · 통합 · 서비스)를 고르고 공통 인풋 6칸과 분류별 인풋 4칸을 채운다. 이슈에는 태그를 붙인다. 태그는 글을 읽고 자동 추천한다.
2. **분석 시작** — 기본 21회 호출.
3. **결과 확인** — 통합 인사이트 3건, 기획 · 디자인 · 개발 · 서비스 담당별 디렉션, 브레인 없이 낸 기본안과의 비교.
4. **고치기** — 연결을 고치고 "다시 묶기", 이슈를 더하고 "새 이슈만 분석".

## 분석 순서

| # | 단계 | 하는 일 | 호출 |
|---|---|---|---|
| ⓪ | 기본안 | 노드 없이 브리프만 읽고 안 3개. 뒤에서 비교 기준으로 쓴다 | 1 |
| ① | 사조 고르기 | 사조 16개 중 4개. 서로 반대되는 쌍 포함 | 1 |
| ② | 분석 | 아이덴티티 6 · 터널 4 · 사조 4가 따로 판단을 낸다 | 14 |
| ③ | 연결 | 판단 사이의 원인 · 조건 · 강화 · 충돌 | 1 |
| ④ | 묶기 | 지지도와 묶음 계산. AI 호출 없음 | 0 |
| ⑤ | 통합 | 묶음마다 통합 인사이트 1건 | 3 |
| ⑥ | 검증 | 모든 노드군을 거쳤는지 ID 집계. 걸리면 1번 다시 쓴다 | 걸린 건당 +1 |
| ⑦ | 통합 디렉션 | 담당별 방향 · 할 일 · 순서, 기본안과 같은 해법인지 판정 | 1 |

## 사람이 정하는 것

- **이슈** — 근본 이슈와 판정 질문. "브리프에서 이슈 뽑기"는 후보만 낸다.
- **노드 지정** — 이슈 설명에 `[[자메뷰]]` `[[타겟]]` `[[브루탈리즘]]`처럼 쓰면 그 노드를 반드시 분석에 넣는다.
- **연결 수정** — 판단을 고르면 연결의 종류 · 무게 · 방향을 바꾸거나 끊을 수 있다.
- **최종 방향** — AI의 판단은 모두 예비 판정이다.

## 여는 법

| 방법 | 명령 | 모델 |
|---|---|---|
| 파일 1개 | `standalone/the-from-brain.html` 더블클릭 | 목업 · OpenAI(내 키) |
| 로컬 서버 | `npm start` → http://localhost:4173 | 목업 · OpenAI(내 키 또는 `OPENAI_API_KEY=… npm start`) |
| 사내 배포 | 이 폴더를 Vercel 프로젝트 루트로. `OPENAI_API_KEY` · `BRAIN_ACCESS_CODE` 설정 | OpenAI(서버 키) |
| claude.ai 아티팩트 | 게시 링크 | 목업 · Claude(보는 사람 계정) |

설치는 필요 없다. `npm install`은 파일 1개로 묶을 때(`npm run build`)만 쓴다. OpenAI 기본 모델은 1.x `knowledge/models.json`과 같고, 화면의 미션 › 모델에서 바꾼다.

## 확인한 것

- **엔진 테스트 20건 통과** (`npm test`).
- **화면 동작** — 헤드리스 Chrome에서 열기 · 분석 · 판단 선택 · 연결 수정 · 다시 묶기. 콘솔 오류 0건.
- **실제 모델 비교 1건** (2026-11-25, Claude Sonnet, `docs/EVALUATION.md`)

| 방식 | 합계(20점) | 호출 |
|---|---|---|
| 브레인 없음 | 12.11 | 1 |
| 1.x | 14.00 | 47 |
| 2.0 | 13.78 | 20 |

2.0은 1.x와 점수가 같고 호출은 43%다. 사조 깊이는 감사자 2명 모두 2.0이 높다고 봤다. 독창성 · 경쟁성 우위는 확인되지 않았다.

## 확인하지 못한 것

- 사람이 채점한 결과. 위 비교는 AI 판정자 3명이 브리프 1건을 본 것이다.
- OpenAI 실제 호출. 호출 형식은 1.x에서 옮겼고, 키가 없어 실행하지 못했다.
- 태그 · 통합 디렉션 · 기본안 대조를 넣은 뒤의 실제 모델 실행. 이 셋은 목업과 테스트로만 확인했다.

## 구조상 한계

- 학습된 신경망이 아니다. 종류가 있는 그래프, 계산식, LLM의 연결 판단으로 구성했다.
- 품질은 ③ 연결에 달려 있다. 틀린 연결이 들어오면 묶음도 틀린다. 그래서 이유를 필수로 받고 사람이 고칠 수 있게 했다.
- 답이 브리프에 적혀 있는 과제에서는 브레인을 써도 기본안과 비슷한 결과가 나온다. 기본안 대조에서 "같음"으로 표시된다.

## 1.x에서 옮기지 않은 것

Positioning 맵 · FoR/PoP/PoD의 웹 조사 · 컨셉 키트(C 게이트) · Creative 가이드 · 이미지 · PPT · 생각의 회차 · 교열 · 지식 동기화 · 비용 장부 · 첨부.

2.0 alpha의 범위는 통합 인사이트와 담당별 디렉션까지다. 웹 조사가 없어 시장 판단의 출처는 `확인 필요`로 남는다.
