# THE FROM BRAIN — FREATIVE 2.0 (alpha)

**단계를 노드로, 단계 사이의 인과와 영향을 엣지로 바꿨다. 모든 노드가 이슈에 동시에 발화하고, 신호가 수렴한 자리에서 통합 인사이트 N건이 한 번에 나온다.**

1.x(`../src`, `../knowledge`)는 그대로 둔다. 2.0은 이 폴더(`v2/`) 안에서만 산다 — 1.x의 빌드(`electron-builder.yml`의 `files`)와 릴리스 워크플로(`package.json` 변경 시에만 동작)에 걸리지 않는다.

## 1.x의 문제와 2.0의 답

| 1.x에서 생긴 일 | 원인 | 2.0 |
|---|---|---|
| A단계의 인사이트가 B로 넘어가며 유실된다 | 단계가 **앞 단계의 요약**을 받는다 | 모든 노드가 **같은 원문**(미션 · 이슈)을 받는다. 요약을 건네지 않는다 |
| 단계 사이의 연결고리가 깨진다 | 관계가 문장 속에 묻힌다 | 관계가 **엣지**로 남는다 — `from · to · 종류 · 무게 · 이유` |
| 결과가 직전 단계만 인용한다 | 통합의 단위가 "마지막 단계" | 통합의 단위가 **수렴한 묶음**. 아이덴티티 · 에어플레인 · 터널 신호를 모두 지났는지 **코드가 ID로 센다** |
| 버려진 것이 보이지 않는다 | 기록이 없다 | 낸 신호 중 몇 건이 인사이트까지 갔는지 건수로 보인다. 쓰이지 않은 신호가 목록으로 남는다 |

## 사고 패스

| # | 단계 | 하는 일 | 호출 |
|---|---|---|---|
| ① | 여행지 고르기 | Airplane 16개 사조 중 발화할 것을 고른다. 대립하는 쌍이 반드시 들어간다 (카탈로그 A-99) | 1 |
| ② | 발화 | 아이덴티티 6 · 터널 4 · 고른 사조가 **동시에**, 서로를 보지 않고 이슈에 신호를 낸다. "누구의 무엇이 달라지는가"를 쓰지 못한 신호는 버린다 | 노드 수 |
| ③ | 연결 | 신호 사이의 원인 · 조건 · 강화 · 긴장을 판단한다. 이유 없는 연결과 같은 노드 안의 연결은 받지 않는다 | 1 |
| ④ | 전파 · 수렴 | 에너지와 묶음을 **계산**한다. AI를 부르지 않는다. 같은 입력이면 언제나 같은 묶음이다 | 0 |
| ⑤ | 통합 | 묶음마다 인과 사슬을 따라 통합 인사이트 하나 | N |
| ⑥ | 가드 | 사슬이 묶음의 모든 노드군을 지났는지, 긴장을 풀었는지, 근본 이슈에 대입했는지 확인한다. 걸리면 이유를 붙여 한 번 다시 쓰고, 그래도 안 되면 **표시해서 남긴다** | 걸린 건당 +1 |

기본값(사조 4 · 인사이트 3)이면 **19회**다. 1.x의 판단 브레인처럼 단계마다 지시 · 검증을 따로 부르지 않는다.

통합 인사이트 하나에 담기는 것: 인사이트 한 문장 · 인과 사슬(신호 ID 순서) · 긴장과 푸는 법 · 지킬 관성 / 바꿀 해석 · 컨셉 방향 · 보이는 표현 · 근본 이슈에 넣은 결과 · N7 문 · 사람이 확인할 것.

## 사람이 끼어드는 자리

- **이슈를 세운다.** 근본 이슈와 판정 질문은 사람이 정한다. "브리프에서 이슈 뽑기"는 후보만 낸다.
- **노드를 지목한다.** 이슈 설명에 `[[자메뷰]]` `[[타겟]]` `[[브루탈리즘]]`처럼 쓰면 그 노드가 반드시 발화하고 신호 강도가 0.15 오른다.
- **연결을 고친다.** 신호를 고르면 연결의 종류 · 무게 · 방향을 바꾸거나 끊거나 새로 이을 수 있다. 그 뒤 "다시 수렴"은 ④⑤⑥만 돈다 — 통합 호출 N회.
- **이슈를 더한다.** "새 이슈만 발화"는 새 이슈에만 ②를 돌린다. 사람이 고친 연결은 지킨다.

## 여는 법

| 방법 | 명령 | 쓸 수 있는 모델 |
|---|---|---|
| 파일 하나 | `standalone/the-from-brain.html`을 더블클릭 | 목업 · OpenAI(내 키) |
| 로컬 서버 | `npm start` → http://localhost:4173 | 목업 · OpenAI(내 키) · `OPENAI_API_KEY=… npm start`면 서버 키 |
| 사내 배포 | 이 폴더를 Vercel 프로젝트 루트로. `OPENAI_API_KEY` · `BRAIN_ACCESS_CODE` 환경 변수 | OpenAI(서버 키) — 키를 직원 PC에 나눠 주지 않는다 |
| claude.ai 아티팩트 | 게시된 링크 | 목업 · Claude(보는 사람의 Claude · 키 없음) |

설치할 것은 없다. `npm install`은 한 파일로 묶을 때(`npm run build`)만 필요하다.

OpenAI 기본 모델은 1.x `knowledge/models.json`과 같다(화가 `gpt-6-astra` · 브레인 `gpt-6.1-sol` · 조수 `gpt-6.1-sol`). 화면의 미션 › 모델에서 바꾼다.

## 확인한 것과 확인하지 못한 것

**확인했다**
- 엔진 테스트 15건 통과(`npm test`) — 호출 수, 결정성, 가드, 재수렴, 이슈 추가, 보고서, 뇌 형상.
- 화면 흐름(헤드리스 Chrome) — 열기 · 사고 · 신호 선택 · 연결 끊기 · 다시 수렴 · 좁은 화면. 콘솔 오류 0건.

**확인하지 못했다**
- **실제 모델로 낸 결과의 품질.** 이 저장소에서 돌린 것은 목업뿐이다. 예시 프로젝트의 문장은 프롬프트 규칙에 맞춰 미리 써 둔 답이다. GPT로 실제 과제를 3건 이상 돌려 1.x 결과와 나란히 놓고 보기 전에는 "특이점이 살아났다"고 말할 수 없다.
- OpenAI 호출 형식은 1.x 공급자를 옮긴 것이고, 키가 없어 실제 호출은 해 보지 않았다.

**구조에서 오는 한계**
- "신경망"은 학습된 신경망이 아니다. 타입이 있는 그래프 + 전파 계산 + LLM의 엣지 판단이다.
- 품질의 병목은 ③ 연결이다. 그럴듯한 헛연결이 들어오면 수렴도 틀린다. 그래서 이유를 강제하고, 화면에서 사람이 고칠 수 있게 했다.
- 병렬 발화는 유실을 막지만 시너지를 만들지는 않는다. 시너지는 ③과 ⑤에서만 나온다.

## 1.x에서 아직 옮기지 않은 것

Positioning 맵 · FoR/PoP/PoD의 웹 정찰과 차별성 판정 · 컨셉 키트(C 게이트) · Creative 가이드 · 이미지 · PPT · 생각의 회차(중간 리뷰 카드) · 교열(AI투 검사기) · 지식 동기화 · 비용 장부 · 첨부.

2.0 alpha는 **통합 인사이트와 컨셉의 씨앗까지**다. 웹 정찰이 없으므로 시장 신호의 출처는 `확인 필요`로 남는다.

  knowledge/
