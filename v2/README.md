# THE FROM BRAIN — FREATIVE 2.0 (alpha)

**어떤 인풋이라도 더프롬 방법론으로 브레인스토밍해, 차별화되면서 실효성 높은 결과를 낸다.**

단계를 노드로 바꿔 동시에 분석하고, 후보를 겨루게 해 고른 뒤, 기획 틀과 디자인 틀로 정리한다. 차별화는 "다름"이 아니라 타겟에게 의미 있고 대신할 수 없는 자리를, 실효성은 "통과"가 아니라 본래 목적을 얼마나 넘어서는지를 뜻한다(`knowledge/criteria.js`).

1.x(`../src`, `../knowledge`)는 그대로다. 2.0은 `v2/` 폴더만 쓰고, 1.x의 빌드와 릴리스에 영향을 주지 않는다.

## 1.x와 다른 점

| 1.x의 문제 | 원인 | 2.0 |
|---|---|---|
| 앞 단계 인사이트가 다음 단계에서 빠진다 | 단계가 앞 단계의 요약을 받는다 | 모든 노드가 같은 미션 · 이슈 원문을 받는다 |
| 단계 사이의 연결이 끊긴다 | 관계가 문장 안에만 있다 | 관계를 연결로 저장한다 (`from · to · 종류 · 무게 · 이유`) |
| 결과가 직전 단계만 인용한다 | 마지막 단계만 보고 쓴다 | 아이덴티티 · 에어플레인 · 터널 판단을 모두 거쳤는지 코드가 ID로 센다 |
| 빠진 내용을 알 수 없다 | 기록이 없다 | 판단 몇 건이 인사이트에 쓰였는지 건수로 보여 준다 |
| 노드를 이름만 읽고 넘어간다 | 정의 요약만 전달한다 | 원문을 읽히고 생각한 순서를 쓰게 한다. 못 쓴 판단은 제외한다 |
| 사조를 해도 되는 것 / 안 되는 것으로 나눈다 | 카드가 "가져올 것 · 두고 올 것" 목록이다 | 시대 조건 · 갈래 · 모순을 읽고, 어느 갈래를 어느 층에서 얼마나 세게 쓸지 해석한다 |
| 평균적인 기준으로 판단한다 | 관점 없이 일반 지식으로 고른다 | 모든 호출이 더프롬의 기준 · 무게 · 판정 사례에서 출발한다. 마지막에 더프롬 판정을 거친다 |
| 터널이 추측으로 채워진다 | 실제 자료가 없다 | 출처가 있는 팩트북을 노드로 넣는다. 팩트 없는 터널 판단은 추정으로 표시하고 비중을 낮춘다 |

## 쓰는 순서

1. **세팅** — 분류(마케팅 · 기획 · 디자인 · 개발 · 통합 · 서비스)를 고르고 공통 인풋 6칸과 분류별 인풋 4칸을 채운다. 이슈에는 태그를 붙인다. 태그는 글을 읽고 자동 추천한다.
2. **팩트북** — AI 조사로 채우거나, md 파일을 불러오거나, 직접 넣는다. 받는 출처는 공식 통계 · 공시 · 브랜드 공식 자료 · 보도자료다. AI가 넣은 항목은 원문을 열어 확인한다.
3. **분석 시작** — 기본 약 51회 호출. 사조와 노하우북은 사람이 고르지 않는다.
4. **결과 확인** — 통합 인사이트 3건과 더프롬 판정(채택 · 보완 · 기각 · 보류, 점수 없음), 기획 틀(Concept Theme), 디자인 틀(Creative 방향), 담당별 디렉션, 기본안과의 비교.
5. **확정** — Concept Theme과 Creative 방향은 사람이 확정한다.
6. **판정 남기기** — 인사이트에 채택 · 기각과 이유를 적는다. 판정 사례로 쌓여 다음 분석의 잣대가 된다.
7. **고치기** — 연결을 고치고 "다시 묶기", 이슈를 더하고 "새 이슈만 분석".

## 사람이 정하는 것

- **이슈** — 근본 이슈와 판정 질문. "브리프에서 이슈 뽑기"는 후보만 낸다.
- **노드 지정** — 이슈 설명에 `[[자메뷰]]` `[[타겟]]` `[[브루탈리즘]]`처럼 쓰면 그 노드를 반드시 분석에 넣는다.
- **연결 수정** — 판단을 고르면 연결의 종류 · 무게 · 방향을 바꾸거나 끊을 수 있다.
- **최종 방향** — AI의 판단은 모두 예비 판정이다.

## 여는 법

| 방법 | 명령 | 모델 |
|---|---|---|
| 파일 1개 | `standalone/the-from-brain.html` 더블클릭 | 목업 · OpenAI(내 키) |
| 로컬 서버 | `npm start` → http://localhost:4173 | 목업 · OpenAI(내 키 또는 `OPENAI_API_KEY=… npm start`) |
| 사내 배포 | 이 폴더를 Vercel 프로젝트 루트로. `OPENAI_API_KEY` · `BRAIN_ACCESS_CODE` 설정 | OpenAI(서버 키) |
| claude.ai 아티팩트 | 게시 링크 | 목업 · Claude(보는 사람 계정) |

설치는 필요 없다. `npm install`은 파일 1개로 묶을 때(`npm run build`)만 쓴다. OpenAI 기본 모델은 1.x `knowledge/models.json`과 같고, 화면의 미션 › 모델에서 바꾼다.

일반 판정자 3명 모두 경쟁 구조의 안을 1위로 뽑았다. 실효성과 경쟁성이 올랐고 독창성은 오르지 않았다. 이긴 안 3건 중 2건은 기본안에 장치를 더한 안이다.

- **3차 · 4차 비교** (지어낸 브리프, 점수 없는 판단 엔진. 안 9개를 Sonnet 판정자 3명 · Opus 판정자 3명이 판정)

| 방식 | 평균 순위(1~9) Sonnet / Opus | 성공 기준에 직접 닿음(18건) | 호출 |
|---|---|---|---|
| 기본안 | 7.89 / 8.00 | 0 | 1 |
| 3차 (판단 엔진 교체) | 5.11 / 5.00 | 0 | 55 |
| 4차 (성공 기준 · 범위 · 같은 해법 재확인, 판단 Opus 5.5) | 2.00 / 2.00 | 16 | 56 |

4차의 개선은 엔진 수정에서 왔다. 같은 결선 요청을 Sonnet에게도 줬더니 30판정 중 27건이 Opus와 같았고 뽑힌 안이 같았다. 4차의 최종안 3개 가운데 2개는 고치는 단계에서 같은 해법이 됐다. 이 문제는 고쳤고 보완 단계만 다시 돌려 확인했다.

- **기조 재실행** — 4차의 최종안 3개와 받은 공격 23건으로 보완 방식만 바꿔 다시 돌렸다. 전부 고치게 하면 서로 다른 해법이 2개로 줄었고, 기조를 세우고 Opus가 보완했을 때만 3개가 끝까지 달랐다(고침 15 · 대가 4 · 받지 않음 4). 같은 기조로 Sonnet이 보완하면 2개였다.

## 확인하지 못한 것

- 사람이 채점한 결과. 위 비교는 AI 판정자 3명이 브리프 1건을 본 것이다.
- OpenAI 실제 호출. 호출 형식은 1.x에서 옮겼고, 키가 없어 실행하지 못했다.
- 실제 모델 실행은 브리프 1건뿐이다. 다른 과제에서도 같은지 모른다.
- 3차 · 4차는 브리프와 팩트를 지어낸 실행이다. 실제 과업과 조사된 팩트로는 돌리지 않았다.
- 기조와 새 오케스트레이션(주 모델 · 보조 모델)을 넣은 엔진의 전체 실행. 보완 단계만 다시 돌려 확인했다.
- Opus 5.5를 제품 안에서 주 모델로 쓰는 길. 호출마다 급은 붙였지만 Anthropic API 공급자가 없다. 평가는 파일 중계로 돌렸다.
- AI 팩트북 조사. OpenAI 웹 검색 호출을 넣었지만 키가 없어 실행하지 못했다. 같은 규칙으로 직접 조사한 예시가 `eval/factbook-앱인토스.md`다(4건, 모두 토스 보도자료).
- 사조 깊이 자료(`knowledge/ism-depth.js`) 16건과 쉬운 말 원리(`knowledge/ism-plain.js`) 80줄은 초안이다. 사내 검수가 필요하다. 프롬프트에는 아직 카탈로그 원문이 들어간다.

## 구조상 한계

- 학습된 신경망이 아니다. 종류가 있는 그래프, 계산식, LLM의 연결 판단으로 구성했다.
- 품질은 ③ 연결에 달려 있다. 틀린 연결이 들어오면 묶음도 틀린다. 그래서 이유를 필수로 받고 사람이 고칠 수 있게 했다.
- 답이 브리프에 적혀 있는 과제에서는 브레인을 써도 기본안과 비슷한 결과가 나온다. 기본안 대조에서 "같음"으로 표시된다.

## 1.x에서 옮기지 않은 것

Positioning 맵 · FoR/PoP/PoD의 웹 조사 · 컨셉 키트(C 게이트) · Creative 가이드 · 이미지 · PPT · 생각의 회차 · 교열 · 지식 동기화 · 비용 장부 · 첨부.

2.0 alpha의 범위는 통합 인사이트와 담당별 디렉션까지다. 웹 조사가 없어 시장 판단의 출처는 `확인 필요`로 남는다.
